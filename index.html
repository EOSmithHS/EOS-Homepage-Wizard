Step 1

Welcome — install your E. O. Smith Teacher Homepage

School Homepage is a personal browser start page that runs entirely in your own Google account. It shows your links in branded category cards, with a type-to-filter box, drag-to-rearrange category tiles, optional To-Do, Important Documents, and embedded Google Calendar cards, a copy button on every URL, and an Edit mode so you can change everything right in the page — no code edits after setup.

This wizard will guide you through copying files into Google Apps Script. It does not directly install the app into your Google account.

What you'll need

  • A Google account (personal or Google Workspace / school account)
  • Access to Google Apps Script — some districts restrict it; if the link won't load, ask your IT department
  • Permission to authorize the app for your own Google Drive (it stores your saved links in one small JSON file)
  • Optional: your school logo as a PNG or JPG — this wizard converts it for you in Step 5
  • About 15 minutes

No spreadsheet, form, or shared folder is required. Everything the app needs, it creates itself.

Step 2

What this app needs

Just your Google account. The app is fully self-contained: it stores your links in one small file (School Homepage Links.json) that it creates in your Google Drive the first time you save, and you'll answer a few quick questions — school name, colors, and optional cards — in Step 4. There's nothing to prepare before you start.

Step 3

Create the Apps Script project

  1. Go to script.google.com/home (button below).
  2. Click New project.
  3. Click the name Untitled project at the top and rename it to School Homepage (or your school's name).
  4. Open Project Settings (the gear icon in the left sidebar).
  5. Check Show "appsscript.json" manifest file in editor — this app includes a manifest, and you'll replace it in the next step.
  6. Return to the Editor (the < > icon).

Step 10

      
Troubleshooting


      
Syntax error: Identifier has already been declared

        
This usually means code was pasted twice, or an old copy was not deleted before pasting the new code.

        
  • Open the file named in the error message.
  • Search for the repeated identifier (for this app, commonly CONFIG, STORAGE_FILE_NAME, or DEFAULT_LINKS).
  • Make sure each appears only once.
  • When replacing a full file, always Ctrl+A / Cmd+A and delete before pasting.

      


      
Authorization Required

        
Open the running web app once and follow the prompts, or in the editor pick doGet in the function dropdown, click Run, and approve the permissions as described in Step 7.

      


      
Access Denied when opening the URL

        
You're likely signed into a different Google account in that browser tab (common with multiple school/personal profiles). Open the URL in the profile that owns the script. Also confirm the deployment says Execute as: Me / Only myself.

      


      
Web app shows an old version after code changes

        
Apps Script deployments do not update automatically. After editing code: Deploy → Manage deployments → pencil icon → Version: New version → Deploy. A hard refresh (Ctrl+Shift+R) helps if the browser cached the page.

      


      
Buttons do nothing

        
  • Confirm the HTML file is named exactly Index — doGet loads it by that name.
  • Confirm you're opening the deployed /exec URL, not previewing raw HTML.
  • Check the browser console (F12) for errors — a partial paste of Index.html is the usual culprit.

      


      
The logo doesn't render (broken image or initials showing instead)

        
  • Logo.gs contains one very long line. If it was truncated during copy/paste, the image data is corrupt — re-copy it from Step 5's converter output.
  • Do not change the template tags in Index.html: <?!= ... ?> must keep its exclamation mark. The standard <?= ?> tag sanitizes data: image URIs away.
  • Confirm the file is named exactly Logo and defines var LOGO_DATA_URI = '...';.

      


      
My edits to DEFAULT_LINKS in the code aren't showing up

        
Expected once you've saved from the page at least once — the Drive file School Homepage Links.json overrides DEFAULT_LINKS from then on. Either make your changes with the in-page Edit button (recommended), or reset: delete the Drive file and clear the LINKS_FILE_ID property under Project Settings → Script Properties.

      


      
The calendar card is missing, blank, or says you don't have permission

        
  • Missing entirely: the calendar link pasted in Step 4 wasn't usable, so the app hides the card. Go back to Step 4, fix the paste (the checker under the box will say “Looks good”), then re-copy Code.gs, re-paste it, and deploy a New version.
  • Blank or “You do not have permission”: the browser is signed into a Google profile that can't see that calendar. Open the page in the right profile, or ask the calendar's owner to share it (Settings and sharing → Access permissions for events / share with specific people).
  • Showing the wrong time zone: the app uses your Apps Script project's time zone when the link doesn't specify one — check it under Project Settings.

      


      
Script cannot find a sheet/tab · Email not sending

        
Not applicable to this app — it uses no spreadsheet and sends no email. If you see errors mentioning these, code from a different project was pasted in by mistake.

Four reminders before you go:

      
    
        
  • Bookmark the /exec URL (and set it as your browser homepage) — it's the only door into your app.
    • 
        
  • Keep the Apps Script project. Deleting it kills the deployment.
    • 
        
  • Protect School Homepage Links.json in your Drive — deleting it resets your links to the defaults (the app recreates it on your next save; nothing breaks).
    • 
        
  • Sharing with colleagues? Don't share your URL — it's locked to you by design. Send them this wizard instead so they get their own copy.
